# Migration redesign

User-approved design: mandatory interactive setup chooses PCR policy and creates passphrase-protected migration key pair. New credentials always policy-authorized, even with PCR disabled, using public-key encryption of each TPM migration authority authorization secret; no unlock required during enrollment. P-256 ECDH/HKDF/AES-GCM, credential and authority bound authenticated data, protect public-key integrity. Serialization of configuration/registration/migration operations; multi-credential operations can partially succeed and default policy updates only on full success. CLI: setup, list --json, info ID --json, migrate --yes (all PCR-bound), config show/passphrase/policy [PCR...|--disable] [--yes]; no PIN API (document fido2-manage). Tables sharp style; integer local ID. Breaking database migration deletes credentials and old recovery config/default policy, preserves PIN. Rename recovery to migration throughout; preserve standard protocol identifiers. Add security review and TPM NixOS tests. Earlier uncommitted session changes must be preserved.

Security review: enforce fixed 32-byte migration authorization plaintext / 48-byte GCM ciphertext, and bound encoded public key input lengths before allocation. Public key/config substitution needs integrity protection at enrollment; same-host MAC has limits against root or compromise of both database and MAC key. Bind every envelope to canonical credential ID, authority public blob/Name and policyRef. No-PCR PolicyAuthorize behavior requires simulator verification. Never silently claim stronger rollback or root-compromise protection.
